# 数据管理

入口：设置 → 数据管理（`/settings/data`）。显示当前数据库、素材、备份目录和作品/素材数量。桌面版与源码版的数据位置可能不同；数量不符时先核对路径，不要初始化或覆盖数据库。

## 备份与恢复

- 点击“创建备份”生成独立目录，包含 SQLite 在线快照、数据库引用的全部原图/结果/版本素材、SHA-256 清单。仅完整备份出现在列表中；素材缺失或复制失败会报错，不会伪装成成功。
- 备份存放在素材目录的同级 `<素材目录名>-backups` 文件夹，不随项目进入回收站而移除。请另存整个备份文件夹到其他磁盘；换机后复制到数据管理显示的备份目录，保留每个 UUID 子目录及内部结构，再刷新页面。
- 点击“校验并预览恢复”检查数据库完整性、外键关系、所有素材校验和及路径，显示待补回作品数量。确认后再执行恢复；恢复前自动创建当前数据的安全备份。
- 恢复采用增量合并：只补回当前不存在的项目 ID 及其页面、原图、结果、版本、分析与任务记录，不覆盖同 ID 作品的当前内容。文件同路径不同内容会拒绝恢复；插入失败回滚数据库并清除本次新复制的文件。回收站内仍存在的项目应使用“还原作品”。
- 必须先停止运行中的任务。恢复的未完成任务保留请求记录，标记为需要人工处理，不自动调用模型或重发不确定请求。
- 当前恢复入口恢复作品数据，不替换整库，不回滚已有项目，也不导入 Provider 配置、API Key、浏览器个人设置或尚未提交的 IndexedDB 上传草稿。数据库快照可能包含旧版存储的加密配置，应作为私人数据保存。旧版本数据结构不兼容时会拒绝导入。
- 本地备份不等于异地备份；应用不自动清理备份目录。

## 回收站

作品列表的“删除”现为移入回收站。保留项目、原图、译图和全部版本；作品列表/分类计数不包含回收站项目。设置中可反复安全地还原。关联批次或单项目任务尚未结束时拒绝移入；回收站项目不能继续修改或开始新任务。当前不提供永久删除或定时清理，防止误删已有数据。

## 图片上传

普通原图每张最多 20MB、4000 万像素，仅接受静态 PNG、JPEG、WebP；风格参考保留每张 10MB 的限制。批量选择总量最多 300MB，每套已保存原图总量最多 300MB，已有项目不会因此被删减。

客户端在读取图片前检查大小和声明格式，服务端限制整个请求体（包括未提供 Content-Length 的请求），核验实际图片格式与 MIME 一致、像素上限、动画页数和图片解码。通过校验后保存原始字节，不压缩、不重编码原图；固定上传标识的重试继续复用已有素材。

验证：`tests/data-management.test.ts`、`tests/upload-validation.test.ts` 在临时数据库和存储中覆盖回收站、关联任务保护、恢复关系、校验失败、文件冲突、重复恢复、未完成请求及上传边界。生产数据不参与破坏性测试。
