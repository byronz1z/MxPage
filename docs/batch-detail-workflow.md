# 首页批量详情页

首页「单商品 / 批量生成」切换，无新增页面。浏览器选择文件夹后先预览分组，再确认整批平台、语言、画质、头图和详情图数量。

## 分组规则

- 所选目录根部的图片，每张是独立商品。
- 每个一级子目录是一个商品，其更深层目录的图片也归入该商品。
- 混合目录同时按以上两条处理。按文件名自然排序，第一张作为主图。
- PNG、JPEG、WebP；非图片忽略并显示数量。超过 50 个商品、每商品 8 张或单图 10MB 时拒绝选择，不悄悄截断。

## 执行边界

固定 workflow 负责分组、上传、排队、逐图生成、版本保存、一次修正上限、结果聚合和取消。官方 Agents SDK 仅用于商品理解与方案规划、单张图片的视觉判断。Agent 不再拥有生成图片、修正图片、完成运行等调度工具；这也适用于单商品、修改和翻译主线。

现有 GenerationTask 保存批次输入与队列，DetailRun 保存每个商品的执行检查点。批次和子任务均使用稳定幂等键。批次先完成一个商品再处理下一个；前端轮询展示已保存套图，不等待全部完成。需要补问、部分完成或失败的商品保留在队列中，并提供作品入口，不阻塞下一商品。

文件上传需要页面保持打开；批次成功启动后由服务端执行，刷新、切换模式或关闭页面不停止任务。浏览器仅保存最近批次 ID。凭据只驻留任务执行内存，不保存到任务记录。失效后台心跳标记中断，由用户点击继续恢复。已完成商品和图片不重新生成，结果不确定的请求只能在作品页明确重试。

停止会取消当前子任务并停止安排新商品；已发出的请求可能完成并保存。处理中断或取消的队列可继续；需补问和已失败的子任务在作品页处理。解决后首页批次视图会同步更新。

## 验证

- `npx tsx --test tests/batch-files.test.ts`：平铺、多视图、混合层级、排序及边界限制。
- `npm run test:detail`：官方 SDK + 模拟 Provider，验证单商品回归、批次幂等、逐套展示、取消和继续、补问隔离、失效心跳恢复、结果不确定时不自动重试、导出等。
- 浏览器验证首页切换、文件夹选择和两种分组预览。真实 Provider 的生成质量及费用不包含在模拟测试结论中。
