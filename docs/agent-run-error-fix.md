# Agent 运行异常排查与复测

日期：2026-09-29。

## 原始现象与证据

- 项目：`cmump9vn0001zjdnkzancdjek`（浅灰荧光黄绿条纹婴儿短袖连体衣）。
- 运行：`cmumpcjil0023jdnk7bvyqdlh`，3 张头图、4 张详情图。
- 原始失败发生在视觉设计阶段，商品规划已保存，尚未开始图像生成。
- 最后一条模型请求在 API 监控中为 HTTP 200；旧 catch 丢弃了异常详情，统一提示“检查 API 配置”。现有证据无法确定原始异常的具体字段，也不能据此认定 Key 或网关错误。

## 修复

- 分类保存阶段、错误代码和脱敏原因，区分鉴权、限流、超时、网络、SDK 协议、工具输入、缺少工具结果与设计质量驳回。不记录 Key、请求正文或完整 SDK 状态。
- 视觉方案工具继续使用同一份严格 schema；在执行入口立即校验，安全提取字段路径作为反馈。格式错误最多自动修正一次，运行轮次有上限。
- 视觉导演必须提交工具结果，修正轮次仍保持必需工具调用；仅格式错误可走格式修正，网络、存储、取消及质量修正次数耗尽继续中止。
- 恢复沿用已保存规划和图片检查点；旧设计驳回记录不再覆盖新发生的接口错误。
- 工作台用中文展示构图与景别检查原因。

## 真实恢复结果

通过浏览器现有凭据执行一次“继续未完成部分”。保留原项目、运行、规划和图片数量，不创建重复规划。

- 本次成功提交视觉方案，越过原先失败的位置；没有发生工具参数格式错误。
- 第一次方案经过文案检查后要求修正；第二次提交未满足“至少三种头图构图”的规则，按次数上限停止。
- 最终状态：设计需调整，0/7 张，图像请求 0 次。未降低验收标准，也未再次自动继续。
- 这是错误处理与检查点恢复验证，不是整套图片生成成功或视觉质量通过。文本/视觉分析请求可能计费，本次未获得厂商实际费用。

## 衬衫视角复核误拦截修正

项目 `cmumr2216002ijdnkfzv77i6n` 的运行 `cmumr79wq002mjdnkd7ovj6bj` 因“三分之二侧向可能展示未知结构”被驳回，图像请求为 0。代码检查确认：设计 Agent 看到了原图和风格参考，文案/分镜复核此前只接收文字事实摘要。

- 设计与复核现在共用相同的高清图片和角色顺序。商品原图用于身份核对；风格参考仅用于摄影和排版判断，不能提供商品事实。
- 将商品视角规则统一传给设计、V2 最终出图提示词及验收：允许裁切、景别、布光、布景和平面旋转，以及保持已知特征的轻微正面透视。视角词本身不能作为虚构事实的证据。
- 只有正面素材时，含糊的侧向描述应明确收敛为正面占主导、未知结构不入镜的镜头；明确要求展示未证实背面、内构、剖面或新增零件时，仍要求修改。实际生成的错误结构仍需验收拦截。
- 保留原有一次设计修正、首图验收和停止规则，没有按关键词删除审查意见或强制通过。
