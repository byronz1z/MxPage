# 模型网关断线恢复

## 实际故障

护肤品套装项目 cmup54012008sjduky1n2jwcp 的任务 cmup55cmv008wjdukcwczoyr0 在规划阶段失败。监控记录：同一 Responses 地址前两次请求成功，后一次在 4789ms 后出现 UND_ERR_SOCKET，未取得完整响应。没有鉴权或地址错误证据；原来的提示把连接中断泛化为“检查网络或网关地址”。

## 修复

- 详情 Agent 的单次模型 HTTP 请求遇到 ECONNRESET、UND_ERR_SOCKET、EAI_AGAIN、ECONNREFUSED 或 HTTP 500/502/503/504 时，间隔 750ms 后最多重试一次。响应正文接收中断也覆盖在内。
- 重试发生在完整响应交给 SDK 之前；重用原请求，不重启整个 Runner，不重新执行已经完成的工具。沿用原请求超时与取消信号。图片生成适配器未改变。
- 401/403、429、无效请求、权限限制、超时不进入这次新增重试。连续失败保留原任务检查点。
- 不带 runId 的商品识别和兼容性探测保留原行为，避免与识别阶段已有重试叠加。每次实际请求均进入 API 监控。
- 连接中断独立显示 PROVIDER_CONNECTION_INTERRUPTED，并只保存允许的 networkCode，保留诊断能力但不记录原始异常中的请求、密钥或上下文。

恢复原任务后发现另一个原有草稿问题：模型把结构化 heroCount/detailCount 设置填写为用户文案要求。新增提示和针对性校验反馈，让模型删除虚构来源的 requirements 项，仍由原流程严格检查 3 张头图和 4 张详情图，不放宽实际张数或商品事实校验。

## 验证

- 123 项测试通过，日志 ui-review/network-recovery-regression.log；TypeScript noEmit 通过。
- Chat Completions 与 Responses 两种 SDK 路径均验证：响应前断线、正文截断、502 后重试成功，完全相同的请求正文，工具只执行一次；持续断线两次后停止；鉴权及限流不重试。
- 工作流回归验证规划中断自动恢复，以及两次中断后保存回答并续跑同一任务；已有图片生成和不确定出图不自动重试的断言继续通过。
- 原任务通过浏览器“继续未完成部分”恢复，规划与分镜复核通过，已保存 5/7 张图片，正在自动修正和继续生成。界面同时提示有 1 张质量检查未完成；图片已保存。验证截图为 ui-review/network-recovery-resumed.png，未据此宣称整套图片或质量验收已完成。

没有修改用户的 API 地址、密钥、模型选择或依赖。
