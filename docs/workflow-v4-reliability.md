# V4 任务恢复与停止

本次修复沿用现有数据库、Provider 与确定性工作流，不增加依赖。

## 恢复规则

- 页面按 `projectId + sectionKey` 保留原 ID，恢复不删除或重新创建已有页面。
- 优先复用页面当前图片、检查点中的资产，以及已落库且关联当前 run 的生成资产。已完成的图片不重新发送生成请求。
- 规划、分镜、逐图检查、分组整套检查均保存结果；恢复只调用尚未执行的步骤。
- 每次请求发出前持久化请求 ID 与 `running` 状态。超时、断网或进程中断留下的请求视为 `uncertain`。
- 默认“继续”跳过不确定请求。用户明确勾选可能再次计费的重试选项时，只授权本次点击之前已不确定的请求各尝试一次，不把授权延续给本轮新失败请求。单张生图的不确定请求最多允许一次此类重试。
- V4 模型调用关闭 SDK 自动重试与自动 JSON 修复；生图接口也不自动切换端点重发。已收到但格式无效的响应同样需要用户明确重试。
- 仅 HTTP 400 且明确拒绝 `response_format` JSON Schema 的请求标记为 `rejected`，用户点击继续可重新提交；不会在当前执行中自动重发。网络错误、5xx、无效返回 JSON 等仍为 `uncertain`，继续遵守计费重试确认。

## 文案与内容覆盖容错

- 新规划传入全套页面编号及 HERO/DETAIL 槽位，覆盖记录使用全套从 0 开始的下标。
- `partial` 表示已安排部分内容且仍有明确资料缺口，不计为完整覆盖。旧草稿中同时带有有效详情页引用和缺口说明的 `needs_input` 本地转换为 `partial`，不删除已知参数，也不编造缺失数值。
- 内容覆盖属于辅助清单，不再作为付费流程的失败条件。重复记录、失效页码、状态与页码冲突在本地整理；没有资料的模块保持待补充，不虚构覆盖率或事实。
- 尚未开始分镜/生图时，程序将仅在 HERO 中的完整内容及证据补入有容量的 DETAIL，保留原页面与全文。超出容量或已有分镜/图片时保留现状并提示核对，不删减内容、不重做图片。
- 取消 `PLAN_CONTENT_REPAIR` 请求与对应按钮。旧版遗留的修复请求账本保留，但继续任务不再发送该请求，不论旧请求成功、失败还是超时。
- 允许分镜自然润色标题、句式、标点与换行，不再对规划逐字验收。参数行或尺寸表单元格丢失、正文被明显删短时，从规划本地补齐并重排；只有页数与分镜位置无法对应等结构问题仍需暂停。
- 字号、位置的无效值使用默认值并归一化，换行由程序生成，保留数字、英文单位和尺寸组合；不再因模型旧换行而追加模型调用。
- 内容差异和整理结果只写入 `contentWarnings`，在预览下方“内容整理提示”中折叠展示，不影响完成状态。逐图和整套质检关注事实、信息完整性与可读性，不把同义改写或标点差异当成缺陷。
- 旧任务中的 `sections[n].textBlocks`、`Typesetting` 和内容覆盖诊断转换为继续操作提示。继续时复用原规划、分镜和已完成图片，无法确认结果的付费请求仍须明确重试授权。

## 停止与执行权

- 每 15 秒续约 60 秒执行租约，等待模型期间也持续心跳。
- 每次调度和数据库写入都验证执行权。失去执行权的旧 worker 不能覆盖检查点、任务状态或页面当前图片。
- 停止后不再调度下一次请求；已经发出的请求等待结束并保存返回结果。收尾期间保留租约、禁用继续，避免并行重跑。
- 停止不会撤销 Provider 已接收的请求，也不能保证 Provider 不计费。应用不会因停止自动补发该请求。
- 同时点击继续通过条件更新与 worker 去重，只启动一个执行器。

## 检查状态

- `COMPLETED` 必须所有图片已保存、逐图检查通过且整套检查通过。
- 图片已生成但检查超时或缺失，状态为 `PARTIAL`，提示“质量检查未完成”。检查发现问题同样保留图片，不自动重生成。
- 12 张以内执行一次整套检查；超过 12 张分组，每组最多 12 张，相邻组重叠一张以检查衔接。已完成组会被复用。
- 旧 V4 记录错误标为完成但缺少检查结果时，读取时纠正显示状态，不触发模型请求。V3 等旧版本不进入 V4 执行器。

## 验证

### 全链路边界加固（2026-10-17）

- 初步识别和复核分别记录请求 ID；每次只调用一次模型，不自动补发网络失败或非法 JSON。按素材与描述摘要复用识别结果，复核失败不会重做识别。首页和配置页均提供明确的计费重试选择。
- 同项目不同幂等键的启动请求也在事务内互斥，防止多标签页同时启动两套付费生成。
- 翻译及批次以 `startedAt` 区分执行者；心跳失效停止新调度，旧执行者不能覆盖接管者。译图已落盘但未关联到页面时，恢复可找回资产，不重复生成。
- 逐图质检兼容 V4 结构化问题，并绑定被检查的图片版本；更换版本后不沿用旧检查状态。
- 进度读取有 15 秒超时、渐进重连和卸载取消；资源不存在时停止轮询。HTML 网关响应与无效 JSON 转为可操作提示，不向用户展示解析异常、SQL、SDK 原文或堆栈。
- 补充信息只有提交成功才关闭弹窗；操作已被接受但刷新进度失败，不误报提交失败。异常页面和失效链接提供返回作品入口。
- 生图结果 URL 下载有 45 秒上限，下载失败不会自动重新生图。

### 补充信息卡片（2026-10-17）

- PLAN 在原有请求中结合商品图片、描述与类目生成三个问题，每题三个具体候选答案及一个“自行填写”入口，不预选。依次弹出第 1/3、2/3、3/3 题，支持返回修改，最后一步统一提交。取消多列布局与所有固定占位答案。
- 旧检查点没有具体选项时，用户点击“生成具体选项”后单独补充一次候选，不重做规划或图片。新 PLAN 的候选不完整时也只补充一次。这个请求携带商品图片、描述、已知事实及缺失字段；模型将全部字段归并为三个问题，不丢失待确认项。
- 本地过滤“按现有信息继续”“暂不展示”等处理方式，检查每题三个不同具体答案及所有缺失字段的覆盖；仍不合格时停在确认阶段，允许用户明确刷新候选，不自动循环请求。超时沿用请求账本和明确计费重试保护。
- 用户选择以 `questionId + optionIndex` 提交，后端从检查点取实际选项；自定义模式仅采用去除首尾空白后的填写内容。切换模式后隐藏内容不提交、不进入后续模型输入。检查问题版本、缺答、重复问题和越界选项。
- 轮询、收起及重新打开不清空当前答案；提交失败保留弹窗。全部卡片确认后按原流程更新规划，保存确认记录；不重复追问同一批补充问题。未确认的候选从后续视觉分镜输入中移除。
- 候选仅是待用户确认的推断；按后续要求允许具体模拟数值，需区分模拟值与实测值，不伪造认证。用户仍可自行填写未知或特殊要求，不因缺失字段删掉其他已知内容。补充图片入口保留。已有图片请求的检查点禁止重新提交规划，以免丢失已计费记录。

验证：4 项问答解析测试、6 项问答模拟 Provider 集成测试；全套 249 项通过，TypeScript 检查通过。浏览器在临时隔离样例中验证逐题切换、上一题、选择/填空互斥、最后统一提交及提交失败保留答案。样例页在验证后移除；未提交真实任务或调用付费模型。

### 缺失尺寸跳过确认（2026-10-17）

- 实际“圆柱形蜡烛”任务将尺寸、重量等三组缺失信息全部标为 `blocking: false`，而旧执行器只检查是否存在 `blocking: true`，因此未收到任何用户回答就进入分镜和出图。该任务的规划与实际参数图写的是“尺寸待补充”，没有发现具体尺寸数值。
- 详情页首次生图前，只要 `missingFields` 非空便进入 `WAITING_INPUT`；模型的 `blocking` 标记不再拥有跳过确认的权限。普通继续不能代替回答。确认后的未知字段继续保持未知，不能将用途、规格类型或照片比例当作精确尺寸。
- 已有图片或已发出生图请求的旧任务保留恢复路径，不倒退重做规划或丢失付费请求。检查点中的图片状态、请求账本及同一任务已落库资产共同判断是否已开始生图。
- 新增三项回归：全部缺失项非阻塞时仍暂停、恢复已保存规划仍先确认且不重做规划、已有图片的旧任务恢复不重复生成。问答与恢复测试共 43 项通过，TypeScript 检查通过；使用隔离数据库与模拟 Provider，未重新运行用户任务、未产生真实模型费用。

### 请求格式错误被误报为鉴权失败（2026-10-17）

- 真实两条 PLAN 请求返回 HTTP 400，原因是 `contentCoverage` 被声明成 optional，未进入 strict JSON Schema 的 required 数组。旧错误正则 `invalid.*key` 又错误命中了 `Invalid schema ... every key`，把格式错误显示成鉴权失败；同期模型发现和连接检查均成功。
- 使用已安装 OpenAI SDK 的 `zodResponseFormat` 转换并在发出请求前验证 schema；覆盖清单改用默认空数组，继续容忍返回内容缺失或无效。API 格式约束与本地文案容错分开。
- 鉴权分类优先采用真实状态码及明确的密钥错误词，不再泛匹配任意 `invalid...key`；格式拒绝有单独提示与请求状态，不要求更换密钥。
- 测试 Provider 递归检查每个请求对象的 required 与 additionalProperties，覆盖识别、规划、补充选项、分镜及质检。新增真实 400 文本回归、格式修复后手动继续及不支持 schema 在请求发出前拦截的测试。
- 完整测试集 268 项及 TypeScript 检查通过。验证过程中捕获并修复了重复点击补充选项时的状态读取竞态：复用已启动任务，取消任务收尾仍保持等待。
- 准备修正两条旧失败记录时，发现它们已不存在，事务回滚，未改动其他任务；未自动启动任务、未调用真实付费模型。
- 本轮新增测试的静态导入造成环境配置早于临时目录初始化，误清了应用消耗日志。已修复导入顺序并增加写入/清理之前的隔离路径断言；恢复资料保存在 `test-output/usage-log-recovery`。目前保留 251 条服务器调用摘要和 47 条旧快照，原始消耗日志未完整恢复，未用不完整数据伪造监控统计。
