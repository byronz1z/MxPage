# 详情页与头图：参考拆解、反推提示词与落地

日期：2026-09-29。对象：用户提供的 11 张电商案例；优化目标是生成图片本身的设计质量。

## 这次实际发现的问题

旧生成请求同时叠加业务方案、通用视觉要求、历史风格和大量 JSON。其中仍有“背景克制”“商品完整展示”的统一要求，容易把不同任务压成白底居中商品加标题。即使方案写了不同模块，最终请求也没有稳定地落实镜头、商品比例、文字区域和材质。逐图检查以商品和文字正确为主，无法区分“没有错误”和“设计完成度足够”。

这次把内容规划和画面设计拆成两个固定阶段。商品事实与文案先确定，视觉导演再为全套图片完成分镜；程序检查分镜后才允许图像请求。没有给 Agent 增加自由出图或无限返工权限。

## 11 张参考的反推

以下是基于画面观察的设计判断，不是原作者实际使用的提示词。只学习设计方法，不继承案例中的品牌、价格、赠品、功效、销量或认证。

| 参考 | 形成视觉效果的关键 | 可迁移的提示词表达 | 对应方案 |
| --- | --- | --- | --- |
| 1，荧光绿洗发水 | 大瓶右置、微倾角，左上粗黑主张，浅底与高饱和底带形成强主次 | 原商品占据画面右侧主要区域；左上短粗标题；包装提取的亮色形成单一大色块；明确接触阴影，减少零碎装饰 | 高对比品牌主视觉 |
| 2，白黄气泡水 | 上方编辑式排字，中部斜向商品节奏，黄色弧线串联，底部信息收束 | 用宽弧线组织视线；大留白中安排不同距离的商品；标题与物体错位；包装组合须由真实 SKU 支持 | 轻盈编辑式 |
| 3，蓝白防晒 | 纤细大字与大产品对比，椭圆色面、弧线和冷色调统一 | 天蓝与白色，明确椭圆平面；双产品仅在确有两件商品时使用；产品边缘干净，标题和产品各有完整区域 | 清透几何 |
| 4，钴蓝饮料 | 饱和蓝、白黄大字、斜置金属罐，主体有冲出画面的力量 | 深饱和色场，白色大字和单一暖色强调；允许次要物体边缘裁切；控制高光；不生成无意义英文边框 | 钴蓝冲击 |
| 5，黑白营养品长页 | 深浅章节交替；手部、产品、信息图、证据和规格承担不同任务 | 暗色立体主视觉接米白信息屏；插入真实可见细节或使用场景；有证据才画数据图、证书或参数 | 黑白精密 |
| 6，巧克力米饼长页 | 奶油与可可色、波浪衔接、食物近景、手势、图文组与 FAQ | 温暖食欲光线；用宽波浪衔接章节；有材料才展示断面、原料和包装数量；不复制角色、Gif 字样或演示板 | 暖调食欲 |
| 7，绿色洗护长页 | 鼠尾草绿、通透材质、植物光影，大产品与微观画面交替 | 玻璃曲面和叶形光影营造氛围；包装外观固定；植物造型不等于配方事实；大场景与材质特写有节奏 | 植萃通透 |
| 8，蓝白洁面长页 | 瓶体、泡沫、手部、功能图组和档案页交替，信息密度有变化 | 浅水蓝与白色；产品摄影、使用动作和信息分组交替；质地和测试必须有依据；不生成 Overall display 或外部展示框 | 水感质地 |
| 9，深蓝洗发水长页 | 深蓝银白、玻璃建筑感、细金线、人物、特写与数据屏交替 | 暗色空间的方向性反射与亮色解释页交替；精细字体层级；有依据才展示专利、前后对比或实验效果 | 深蓝精致 |
| 10，白绿洗发水 | 衬线大标题、侧边通透曲面、商品与文字列表有克制的非对称关系 | 暖白与橄榄绿，流动玻璃在边缘引导；大标题留呼吸；将可证实利益排成少量清晰层级 | 植萃通透的编辑变体 |
| 11，暖米色精华 | 石材层次、温暖柔光、中央瓶体与两侧大数字形成高级感 | 真实商品置于有触感的矿物布景；大柔光形成细腻明暗；只有提供真实数据才使用大数字，否则改为简短事实文字 | 矿物暖奢 |

另外保留生活方式叙事方案，适配服饰、家居、家电。当前共 11 种视觉方案，不将一个品类绑定为一种颜色。实际选择还取决于包装、客群、商品事实和用户指定方向。

## 搜索后采用的方法

OpenAI 的官方图像提示词指南建议把广告请求写成包含受众、概念、构图和准确文案的创意简报；明确各输入图的角色，并在修改时区分要改变与要保留的部分。这次用于分镜字段、原图/待修改图/风格图的编号映射，以及修正范围的处理。[OpenAI 官方指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)

Baymard 的产品页研究说明，产品图片配合简短文字和图解能帮助用户理解不明显的特征；按重点组织内容也有助于浏览。这次用于“一屏一个购买问题”，而不是把商品分析原文铺成图片中的长段落。[图片与说明](https://baymard.com/research-articles/product-images-descriptive-text)、[按重点组织内容](https://baymard.com/research-articles/structure-descriptions-by-highlights)

这些资料不证明自定义网关模型的能力，也不保证最终生成质量。模型 ID、网关和用户选择的画质保持原配置。

## 新流程和约束

1. **内容规划 Agent**：确认品类、客群、产品定位、事实来源和每屏任务，输出最终文案。减少“简洁外观”“可见印字”这类泛泛标题和审查备注。
2. **图像提示词 Agent**：使用官方 Agents SDK，整套只运行一个设计阶段，最多 3 个 SDK 轮次。读取原商品图，选择视觉方案，并为每个实际 section ID 指定构图、密度、商品比例、位置、镜头、背景、光影、图形元素、文字块和上下屏衔接。
3. **程序校验**：每个 section 只能出现一次；文字不得新增或遗漏；头图组和详情组各至少三种构图、两种商品比例；相邻详情不能重复同一构图/比例/密度组合。失败返回设计阶段修正，仍失败则暂停，不出图。
4. **提示词编译**：只带入选中的视觉方案与当前图片的方向。新版不再叠加旧的“克制背景、完整居中”等要求。每个参考输入有准确序号，明确身份、修改源或风格用途。
5. **逐图检查**：除事实与文字外，要求提交主次层级、构图执行、光影材质、字体排版四项判断。任意失败都不能判为完整通过。修正最多一次；构图有问题时允许修正构图，不再强制保留错误版式。
6. **整套检查**：查看实际输出的头图与详情，检查重复构图、信息任务、色彩/材质、文字层级和长页节奏。不追加一轮收费出图。

视觉检查依然是模型判断，不是人类设计师验收，也不是销售效果预测。

## 对充电器的设计示例

这是人工反推的设计意图，**不是本次真实模型生成结果**。此前能确认的是黑色充电器外观、可见圆脚、蓝色接口区域、可见 HAVIT / 65W 印字；不能把印字直接升级成快充协议、实测功率或兼容承诺。

**头图的画面意图**：用黑白精密或深蓝精致方案。保留原机身、接口与圆脚，不复制原白底。让商品在深石墨色摄影场中略偏右放大，窄轮廓光勾出黑色曲面，一块暖白几何平面把标题与商品分开。主标题只写真实的商品身份或有依据的特点，不用空泛的“品质之选”，也不新增“氮化镓”“极速快充”等文字。

**详情的节奏意图**：主视觉 → 浅色外观与实际可见结构组合 → 深色接口近景 → 真实尺度不作承诺的桌面氛围 → 圆脚与壳体细节的编辑分栏 → 仅含已提供信息的收束页。没有尺寸、协议、配件事实，就不画尺寸表、兼容矩阵或包装清单。画面丰富度由摄影与编排承担，不能靠编造卖点补齐。

**一张特写提示词的骨架**：

```text
3:4 电商详情模块。黑白精密视觉体系，深石墨与暖白形成主次。
使用原图中已经可见的接口一侧，不创造背面或内部结构。
商品局部偏右放大，特写允许裁切；保留接口形状、蓝色区域和真实壳体比例。
柔和侧光体现曲面，窄轮廓光分离深背景；不要把黑色表面变成银色金属。
左侧暖白文字区放置本模块已确定的短标题及准确说明；不增加其他文字。
主体与文字之间用细线引导，底部色面延伸至下一屏，不加卡片外框。
原始素材负责商品身份；上一张成品仅供色彩、光影与字体参考，不复制构图。
```

生产请求由保存后的结构化分镜编译，包含每个文字块的实际内容、字号等级、颜色和位置，不会把上述“短标题”等描述渲染成占位文案。

## 验证与使用范围

- 自动测试用本地模拟 Provider，经真实 Agents SDK、数据库、图片适配器和导出流程运行，不调用收费模型。
- 覆盖：设计阶段失败时零图像请求、错误分镜反馈修正、保存用户原始方向、恢复不重复设计、不重复出图、审美失败限次修正、完整请求携带编译分镜，以及批量、小红书、翻译兼容。
- 最终验证：35 项测试全部通过；TypeScript 检查通过。用户方向快照修复也已纳入复测。测试日志：`art-direction-test.log`。
- 本轮没有新做真实模型出图或人工 A/B 视觉验收，不能把测试通过表述为“图片已经达到参考水准”。
- 新创建的详情页任务自动使用此流程。已有成品和已出图的运行不会被静默重做；中断恢复使用原来的检查点。新流程生成的图片在后续修改/重新生成时复用其视觉分镜。旧项目仍可打开、修改、导出。
- 工作台“整页设计方案”展示最终选定的视觉方向、概念、配色和光影，避免仍显示已被替换的初步方案。

实现入口：`lib/detail-runs/art-direction.ts`、`lib/detail-runs/service.ts`；内容规则：`lib/detail-runs/merchandising.ts`、`lib/detail-runs/creative-rules.ts`。
