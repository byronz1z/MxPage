# 商品详情规划 v2 与淘宝预览

2026-09-29。本次以用户提供的淘宝双屏截图和食品、家电、便携风扇详情页参考为依据。

## 本次已落地

- 新建电商任务使用 v2 结构化规划：品类、人群、产品主张、事实来源、整套视觉系统，以及每屏购买问题、目标、事实引用、版式、构图和上下屏衔接。
- 七类策略：数码、家电、食品、服饰、美妆、家居、日用。食品偏食欲和原料质感，家电偏居家场景和功能组，数码偏光线、接口细节与参数解释；不将参考图中的具体卖点当作用户商品事实。
- 素材作为商品身份依据，允许重设背景、灯光、场景、字体与构图；保留 SKU、形状、颜色、标识和可见部件。
- 程序检查数量、来源 ID、事实引用、首屏定位、版式多样性、购买问题与完整文案重复。无依据的规格由模型省略或补问，不使用检查备注凑广告内容。
- 图像请求由固定 workflow 发起。首张通过检查的图可以作为后续图片的风格参考，原图继续约束商品身份；实际请求提示词完整持久化。
- 逐图检查、最多一次修正后，增加一次整套视觉检查。整套检查会识别重复叙事、排版雷同、风格不统一和移动端可读性问题；失败标记 PARTIAL，不触发额外重生成。检查中断后可只恢复检查。
- 第二步可以选择品类、查看其推荐叙事与视觉；结果工作台提供可展开的逐屏方案和事实依据。
- 淘宝参考预览使用 375×812 逻辑画布：主图轮播、商品信息、服务/规格、评价/店铺区域、连续详情、固定购买栏。滚动后导航出现，图片可以放大，购买栏弹层仅为本地模拟。另保留通用预览。
- 预览的售价、运费、店铺等信息可填写并保存；缺失数据明确显示为空，不虚构销量、评价、优惠、店铺评分。预览界面和这些信息不会写入导出图片。

## 数据和兼容

沿用现有表及 JSON 字段。旧方案和图片不会被重生成；旧运行保留原检查点恢复能力。小红书使用原方案契约。批量电商共享新流程，批量翻译继续使用翻译流程。

复用 Next.js、官方 Agents SDK、Zod、Radix Dialog、Lucide、Sharp 和已有任务/版本/导出能力，没有新增依赖。
