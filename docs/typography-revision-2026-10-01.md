# 商品图文字编排修正

## 实际问题

检查榴莲项目的主图、外壳／剖面页、重量页和参数页后发现：整句粗黑标题反复占据顶部；规格数值被放成多个同等大的标题；引线、金色装饰与信息层级无关。旧方案只有 display/body 等尺寸标签与自由描述，没有具体分行、字号和文字区域。另外，“先看果肉形态”“外壳与剖面，都是选购参考”仍是观察报告，改变字体无法解决其文案问题。

## 生成链路修改

- 每个 textBlock 支持 typesetting：精确分行、文字区 x/y/width、字号、字重、行距和对齐。位置使用画布百分比，字号以 375px 手机预览为基准；头图高度 375、详情图高度 500，按实际输出宽度缩放。
- 新设计提示词要求填写排版数据；历史字段允许省略，不新增必填导致旧检查点无法续跑。缺少数据时使用原定位和新增层级规则。
- 校验分行不得修改原文字、标点、参数或单位，检查显式文字区越出右边界／底边界。不把主观审美评分或估算字宽作为硬性提交门槛。
- 头图、标注、叙事和规格采用不同阅读结构。参数标签／数值采用相近字号、对齐列、均匀行距，避免每项参数都是展示标题。字号区间是默认指导，实际可读且合理的设计允许变化。
- 新增 typography 复核类型，必须局部更改文字或排版，空修改和仅改变摄影不能消除缺陷。单图复核检查真实层级和手机可读性，不能只检查文字正确。
- 针对榴莲案例拦截 AI 主标题中的具体观察报告模式。局部标签和用户明确要求的原句保持有效；食品文案可表达享用场景与情绪，不从照片推断甜度、成熟度或口感。

## 验证

- TypeScript noEmit 通过。
- 116 项测试通过：ui-review/typography-regression.log。
- 新增分行／事实保持、画布边界、旧方案和纯摄影兼容、参数表规则、局部排版复核及 SDK 模拟工作流测试。集成测试确认复核后的字号与分行进入保存的出图提示词，原文案、其它页与参数页保持一致。
- 使用同一真实商品参考、经过生产编译器输出的提示词生成两轮样图。第一轮仍偏粗黑；第二轮明确宋体字形关系并缩短标题，形成宋体主标题和无衬线信息的区别。预览脚本：ui-review/preview-typography.ts；最终样图：ui-review/typography-preview-v2.png；完整提示词：ui-review/typography-preview-prompt.txt。

样图是手工策划的验收输入，经同一编译器交给内置 imagegen 生成，用于检查提示词执行效果。它不是应用所配置厂商的全套实测，也未覆盖原项目图片或自动激活新版本。生成模型仍可能偏离坐标与字重；实际出图验收需要继续检查最终像素。

无新增依赖、数据库迁移或页面 UI 改动。
